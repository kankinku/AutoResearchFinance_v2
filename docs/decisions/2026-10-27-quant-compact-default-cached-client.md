# ADR — Quant 대화 클라이언트 캐시의 기본 응답 압축

- 결정일: 2026-10-27 KST
- 범위: 기존 T4(ChatGPT↔Quant MCP) 의존 작업. Q02/Q06/Q08/Q15/Q16/Q17/Q20.
- 사용자 승인: 2026-10-27 대화에서 응답 압축·서버 연구 기억·대화 간 복원을 포함한 단계별 개선 계획을 제시한 뒤, 사용자가 **「위 내용에 따라서 진행」**이라고 명시적으로 지시함. 별도 GPT SDK 모델 호출, 새로운 연구 목표, 거래 승인은 포함하지 않는다.

## 문제·근거

2026-10-26 운영 서버에는 `get_algorithm_research`, `submit_algorithm_plan`, `submit_algorithm_diagnosis`의 `response_mode=compact` 기능이 이미 배포되었으나, 현재 ChatGPT 연결이 기억하고 있는 32-tool 입력 계약에서 해당 선택 인자는 보이지 않는다. 클라이언트에서 압축을 요청할 수 없어 68세대 원장 기준 약 701KB의 `history`가 매 호출 중복 전송될 수 있다. 기존 서버의 명시적 compact는 같은 원장을 약 110KB로 렌더링했다. 이 바이트 수는 GPT 토큰·무인 실행 횟수를 뜻하지 않는다.

## 결정

- **기존 세 학술 도구에 한해** `response_mode`를 생략하면 서버의 **출력 표현만 compact**로 반환한다. 기존 캐시된 ChatGPT 입력만으로도 동작한다. 새 공개 도구를 추가하거나 OAuth 재발급/기존 URL 재등록을 하지 않는다.
- 최신 세대 Evidence/해시, 체크포인트 토큰, 부모 계승 결정, phase 및 타입드 model_context를 보존한다. 원본 canonical SQLite와 계획/진단 제출 인자는 동일하다. 명시적 `response_mode=full`은 종전 원본 전체 응답을 그대로 제공한다.
- 압축 읽기 불가 시 명시적 오류·미변경 원장; **성공한 쓰기의 표시만 축약 실패**하면 원래 성공 응답을 반환해 중복 제출을 유도하지 않는다. 기존 128KiB compact 상한 유지. 판정에 필요한 정보를 조용히 생략해 32KB를 강제로 달성하지 않는다.
- 기타 MCP 읽기 도구의 `summary/full` 기본값, GPT 연구 엔진, 32개 도구의 required 인자, 현재 세대/부모/평가 문턱, 기존 OAuth/URL, 실주문 OFF, 봉인 OOS는 불변.

## 호환성·롤백

이 변경은 입력 ABI는 유지하나 **생략형 학술 결과의 출력 기본 표현**을 바꾼다. 종전 생략형 응답에서 전 세대 `history` 전체를 파싱하던 타 클라이언트는 `response_mode=full`을 명시해야 한다. 따라서 배포 시 모델/소비자 계약과 실제 운영 데이터의 무변경을 반드시 확인한다. 문제 발생 시 이 어댑터 변경만 전 버전으로 되돌리고, 연구/SQLite 데이터는 롤백·삭제하지 않는다. 클라이언트 캐시 자동 갱신은 서버에서 보장하지 못한다.

## 수락 기준

1. 32 tools/필수 인자 및 `full` 조회 동일성 확인.
2. 인자 생략 `GET → PLAN → DIAG → GET`에서 추가 자동 GPT 호출 없이 최신 증거/토큰·상태 보존.
3. 10/25/50/100 **합성** history 전송 바이트 비선형 증가·128KiB 이내. 실제 GPT 100세대 완결·모델 토큰 소모는 별도 T4 실험.
4. 개발 저장소 tests→Ruff/Mypy→full suite→배포 전 백업/인증 MCP smoke 순. 원장과 서비스에 미반영 상태를 구분하여 기록.

원래 V05→T4→V01–V04→V06→V07 순서, 원본 20문답 및 범위 잠금 유지.
