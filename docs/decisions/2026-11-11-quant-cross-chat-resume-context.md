# Quant: GPT 대화 압축 및 새 대화에서 연구 복구

상태: 사용자 명시 승인 (2026-11-11). 원문: "Gpt의 세션이 초기화 혹은 압축이나 새로운 곳에서 시작되더라도 할때마다 필요한 정보를 가져오도록. 만들자. (모든 데이터를 세션에 가지고 있으면 힘들어)".

## 범위 · 기존 정책
- T4 연구 세션을 서버 SQLite 체크포인트에서 재발견하고 필요한 시점에 읽기(Q02/Q06/Q08/Q09/Q15/Q17).
- 기존 32개 MCP 도구 및 JSON 스키마 유지. 기존 get_research_brief의 응답에 한정해 실시간 진행 세션 정보만 추가.
- 기존 get_algorithm_research를 세대별 상세/작성 스키마/체크포인트 토큰의 유일한 출처로 사용. 대화 메모리 또는 요약 파일은 정본이 아님.
- 2개 이상의 활성 세션이면 임의 선택 금지. 미확인/손상된 원장은 정직하게 실패. 토큰은 요약에 반환하지 않음.
- 원본 OAuth/URL, 주문 차단, 비PIT 개발 제약, 기존 G150 비계승, 최신 G10/40 원본은 보존. 자동 백그라운드 GPT 실행은 범위 밖.
- 모든 새 ChatGPT 대화에서 사전 메시지 없이 도구 호출을 강제하는 기능은 MCP만으로 보장할 수 없다. Quant 관련 첫 요청 시 MCP get_research_brief 조회를 도구 설명과 운용 안내에 기록한다.

## 인수 시험
1. 세션 ID를 잃은 GPT가 get_research_brief로 최신 활성 연구의 ID·목표/완료·단계·다음 행동·최근 증거·S7 개요를 발견한다.
2. 0개/1개/복수/중단/완료 세션을 구별하고 추정으로 진행하지 않는다.
3. 요약 8KiB 이내, 기존 전체 overview 24KiB 이내. 필요할 때만 get_algorithm_research(compact/full)로 원본 스키마/토큰/근거 획득.
4. 서버 시점에 canonical 해시 검증 및 상태 조회. 요약·상세 API 호출 자체는 연구 세대·증거를 추가하거나 수정하지 않는다.
5. 32개 MCP 이름/입력 스키마 불변, 기존 OAuth URL/등록 토큰 불변, 주문/OOS 승인 거부.
