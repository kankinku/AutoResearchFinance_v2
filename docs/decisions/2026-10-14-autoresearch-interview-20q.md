# Quant Autoresearch — 사용자 20문답 결정 기록

기준일: 2026-10-14. 사용자의 **직접 답변**을 요약·보존한다. 선택지의 문장을 사용자 결정인 것처럼 확대 해석하지 않는다. 본문은 요구사항이며 새로운 임계치·구현 세부는 별도 추진안으로만 적는다.

| 번호 | 질문 | 사용자 답변 (의미 충실 요약) | 설계에 미치는 영향 |
|---:|---|---|---|
| 1 | 개발 방향의 문제 | 자동 연구 엔진보다 개별 매매전략 개선에 치중 | 개별 QQQ 모멘텀 수동 최적화를 우선 목표에서 제외 |
| 2 | 자동화 수준 | 완전 자율 연구형 | 연구 대상을 정하고 생성·평가·진화하는 자율 연구 엔진 |
| 3 | 시장 범위 | 유망 시장부터 엔진이 선정하고 단계적으로 자율 확장 | 광범위한 일괄 탐색보다 단계적 확장 |
| 4 | 연구 우선순위 | 실제 실현 가능한 예상 **순수익** | 거래비용·유동성·거래 가능 규모 반영 |
| 5 | 전략 발굴 | 기존 연구 완료 전략/논문/오픈소스를 '인디케이터'로 구성, LLM이 조합하고 상황에 따라 전략 전환하는 **알고리즘** 제작 | 지표가 최종 제품이 아닌 구성 요소; 시장 상황별 정책·조건식·가중치 자유 설계 |
| 6 | LLM 역할 | LLM이 조합·매개변수·논리 구상 → 다양한 자산 백테스트 → LLM 결과/원인 분석 → 다음 개선; 초기 무작위 탐색 고려 | 매 세대 백테스트 피드백을 받아 연구 판단하는 루프 |
| 7 | 연구 진화 방식 | 초기 무작위 데이터 축적, 이후 우수 알고리즘 진화+LLM 가설 검증+무작위 탐색 병행, 비중 자동 조정 | 탐색·활용·가설 연구의 적응적 조합 |
| 8 | 연구 메모리 | 모든 실험/원인 분석 축적, 중복 방지, 가설 재검증, 증거 보충 실험 자동 설계 | 긍정·부정·미결 연구 및 근거 보존 |
| 9 | 결과 평가 | 가능한 모든 수익·위험·거래 지표 자동 계측, LLM은 당시 환경·알고리즘 요소별 손실/낙폭 **원인** 탐구 | 수치 자동 계측과 LLM의 해석/가설을 엄격 분리 |
| 10 | 알고리즘 자유도 | 등록된 인디케이터 기반으로 조건 분기·상황별 전략 전환·가중치·논리 구조 자유 설계 | 타입드 조합 언어/IR 표현력 확장 |
| 11 | 구현/백테스트 | 오픈소스 라이브러리 지표 호출, LLM 조합식→백테스트. 각 체결의 식별코드·성과·당시 지표값·매매 의견 형성 근거까지 기록. 논문/설명형 지표 구현·검증 모듈도 필요 | 복합 조합 엔진, 결정·체결·손익 추적, 지표 검증 파이프라인 |
| 12 | 지표 확보 | 초기부터 기존 오픈소스 지표 폭넓게 확보, 연구 중 논문·신규 지표 자동 확장 | 초기 라이브러리 + 수요 기반 확장 병행 |
| 13 | 백테스트 범위 | 동일한 기준 자산/기간으로 시작, 성과가 있으면 범위 확대 | 공통 연구 조건, 후속 검증 점진 확장 |
| 14 | 다음 단계 통과 판단 | D+E. 전체 성과 저조해도 특정 환경 강점·개선 여지 고려. 자동 성과 평가와 LLM 원인 분석을 결합 | 단일 수익률 컷오프만으로 모든 연구 중단 금지; 확대/수정/중단 결정 |
| 15 | 연구 실행 | A+B. N세대 명령 실행과 중단까지 지속형 모두 | 두 운영 모드 공통 세대 엔진 사용 |
| 16 | 사용자 보고 | 최종 성과와 핵심 개선만 요약 보고 | 내부 세부 기록은 유지, 기본 사용자 응답은 간결 |
| 17 | 세대 정의 | 알고리즘 생성→백테스트→분석→후속 연구 방향까지 1세대; 후보 수·탐색 비율·재검증 횟수 자율 조정 | **세대 ≠ 백테스트 수**. 분석/후속 계획 없으면 세대 미완료 |
| 18 | 개선 방식 | 원인 탐색 기본, 인디케이터 추가/제거 등 다양한 해결책 허용 | 원인 기반 가설·수정·대조 검증, 고정된 변경 패턴에 갇히지 않음 |
| 19 | 개발 범위 | A+B+C+D 모두 진행 | 자율 루프, 지표 라이브러리, 상세 추적, 최소 통합형 모두 범위에 포함 |
| 20 | 성공 기준 | 1차 자율 연구 엔진 완성 → 2차 LLM 원인 분석·진화 검증 → 3차 다자산 수익 알고리즘 발견·독립 검증 | 단계별 완료 판정 분리. 연구 기능 완료 ≠ 수익성 입증 |

## 정확한 의도

1. **Indicator / Algorithm 구별**: 인디케이터는 매매에 필요한 관측값과 계산 도구; 알고리즘은 여러 인디케이터를 상황별로 조합하고 진입·청산·노출 등을 판단하는 복합 규칙이다. 엔진이 자율 발전시켜야 하는 대상은 알고리즘이다.
2. **LLM / Evaluator 구별**: 백테스트 숫자·거래 원장은 기계적으로 계산, LLM은 그 값들을 참고해 원인을 *가설*로 제안. 원인으로 입증하려면 후속 실험을 해야 한다.
3. **1세대 완료 조건**: 후보 생성, 실행, 기록, LLM 분석, 다음 세대의 연구계획이 모두 성립해야 완료이다. 동일 전략을 재평가한 횟수로 세대를 부풀리지 않는다.
4. **성과 목표 / 중간 연구 가치 구별**: 최종 기준은 거래 가능한 순수익이지만, 초기의 낮은 성과 전략도 특화된 시장 환경/개선 가능한 문제가 발견되면 연구를 계속할 수 있다.
5. **고정 기준 데이터와 확장**: 처음부터 여러 시장을 마구 바꾸지 않고, 공통 초기 자산과 기간으로 비교한 후 유망성을 근거로 확장한다.
6. **사용자 인터페이스**: 명령형·지속형 모두 제공. 요약 보고를 기본으로 하고, 내부 상세 감사 기록은 보존한다.

## 아직 확정하지 않은 사항

초기 고정 자산 및 기간의 최종 값, 실험/자원 상한, LLM 연결 방식, 통과 임계치, 배포/실거래 권한, 각 시장의 비용과 유동성 모형, 신규 지표의 라이선스 검토 기준. 이 항목은 **설계 선택지**이지 인터뷰에 없던 사용자 결정이 아니다. 임의 완화 없이 별도 정책으로 관리한다.

## 운영 경계

사용자는 실거래 허가를 말한 적이 없다. 기존 protected core/Sealed OOS/주문권한 경계를 유지한다. 과거 승인된 `docs/architecture/quant-autoresearch-architecture-v1.0.md`는 저장소 계약에 따라 수정하지 않는다. 요구 변경은 별도 ADR로 남긴다.
