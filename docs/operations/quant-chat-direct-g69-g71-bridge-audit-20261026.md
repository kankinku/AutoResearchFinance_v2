## 1. 해결한 문제와 해결하지 않은 문제

서버는 `get_algorithm_research`/`submit_algorithm_plan`/`submit_algorithm_diagnosis`에서 `response_mode=compact` 옵션을 이미 구현했지만, **ChatGPT 앱에 설치된 Quant 도구 입력 스키마**는 구버전이라 이 인자를 호출 전에 거절했다. OAuth 또는 앱 연결을 제거하지 않았다.

**검증된 우회 경로:** 현재 ChatGPT 대화 내에서 `functions.exec`가 기존 등록된 `mcp__Quant_AutoResearch__*` 도구를 그대로 호출하고, 반환된 원본 JSON을 그 도구 실행 컨텍스트에서 파싱한다. 그 후 **이 채팅의 GPT에게 필요한 정보만** 표시한다. 계획과 진단 텍스트·타입드 전략은 모두 **현재 대화 GPT가 작성**하고, 실제 Quant MCP에 기존 필수 인자 그대로 전달한다. 별도 Codex SDK 모델 생성/호출 0회. 사용자의 기존 OAuth/고정 URL/플러그인 등록 유지.

**주의:** 함수 호출에 사용된 Quant 서버는 실제로는 FULL 응답(세대당 70만 바이트 이상)을 생성한다. 다만 그 전체 응답을 대화 모델에 그대로 노출하지 않고 필요한 필드만 추려 준다. 이것은 **채팅 컨텍스트 비용/데이터 전달에 대한 우회**이며 서버 내부 응답 생성량, 제공자에게 청구된 모델 토큰, ChatGPT 앱 자체의 메시지·시간 제한이 감소했다는 실측 증거는 아니다. 앱 도구 스키마 캐시는 **여전히 해결되지 않았다**.
