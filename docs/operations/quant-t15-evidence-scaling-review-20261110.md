## 측정 방식과 결과

- 기존 EvidenceStore 공개 API 그대로: **150 / 1,000 / 10,000** 이벤트 크기의 독립 합성 SQLite를 만든 뒤, 각 크기에서 **증분 append 11번(최근접 순위 p95), events() 전체 읽기 5번**, Tracemalloc 읽기 피크, SQLite 무결성·원장 체크섬·불변 트리거·잘못된 이벤트 롤백·150ms 외부 쓰기 잠금 후 복귀를 확인했다.
- 정확히 10,000번 연속 공개 `append()`로 DB를 채우면 기존 알고리즘 자체의 O(n²) 초기화 비용이 시험 범위를 압도하므로 **처음 10,000개는 단일 SQLite 트랜잭션으로 유효한 합성 행을 미리 적재**했다. 아래는 **그 크기에서의 증분 쓰기 지연**이며, 실제 GPT 10,000세대·실 DB 총처리시간이 아니다. 합성 이벤트마다 256바이트 padding을 포함했다.

| 이벤트 수 | 원본 append p95 (1회/반복) | 최종 append p95 (1회/반복) | 최종 read p95 | 사전 append 목표 |
|---:|---:|---:|---:|---:|
| 150 | 23.4 / 26.0ms | **23.1 / 23.4ms** | 10.8 / 10.9ms | ≤30ms |
| 1,000 | 45.2 / 48.4ms | **24.1 / 24.5ms** | 41.4 / 43.1ms | ≤60ms |
| 10,000 | **297.8 / 302.6ms** | **52.8 / 51.3ms** | 352.6 / 353.0ms | ≤100ms |

- 10,000개 증분 append p95는 **약 82.3% 단축**(첫 원본·첫 최종 비교), 독립 반복에서도 목표 안쪽. 10,000개 읽기 기준 **≤800ms** 준수, Python 추적 읽기 피크 **11.916MiB**로 **≤128MiB** 준수. 읽기 지연 자체는 최종과 원본 사이 개선을 주장하지 않는다.
- 쓰기 잠금 150ms를 의도적으로 유지했을 때 최종 10,000개 원장의 대기 후 append는 **230.5 / 233.5ms**에 성공, 원장 무결성·체크섬·불변 트리거/롤백 검사가 각 크기에서 통과했다.
- 구 인덱스 없는 **합성 10,000행 레거시 DB**를 만들어 최초 append에 인덱스를 만드는 경우 **일회성 약 325.6ms** 소요. 원본 10,000행의 콘텐츠 SHA `06898f7f4f34b53149cebeed755f3d2b5dc73c5e973028fc54e4d72b6d23520d` 보존, `PRAGMA integrity_check=ok`, 기존 수정/삭제 금지 트리거 SQL 그대로. **운영 DB에서 이 수치를 확인한 것은 아니다.**

## 최소 변경·반려한 대안

- `memory/evidence_store.py`에 SQLite **복합 표현식 인덱스 `(json_type(payload,'$.research_run_id'), json_extract(payload,'$.research_run_id'), kind)`**만 추가하고, 매번 기존 행의 전체 JSON을 파이썬에서 역직렬화하던 대신 불량 run ID 존재 검사 + **해당 run의 `run`/`manifest`/`end` 여부만 인덱스로 조회**하도록 축소했다. **event 행/체크섬·불변 트리거·풀리더 `events()`·공개 서명 규칙 변경 없음**.
- 중간 대안 1: SQL JSON을 행별 조회해 파이썬 파싱 제거 → 10,000개 append p95 **270.7ms**로 목표 미달, **반려**. 대안 2: `kind` 없는 두 열 인덱스만으로 기존 세대의 `kind` 전체 전송 → **293.5ms**로 목표 미달, **반려**. 최종은 종류 세 가지로 제한한 covering index를 사용한다.
- 성능 원인 계측: 10,000개 같은 세션의 `kind` 목록을 모두 가져오는 조회 약 **236.8ms**. SQL 계획에서 run ID 조회 인덱스 사용을 확인했고, 읽기/시장 데이터/대형 서비스 파일 분할은 하지 않았다.
- 레거시 외부 행에 잘못된 JSON이 있으면 첫 인덱스 생성 또는 다음 쓰기에서 `EvidenceIntegrityError`로 **fail closed**. run ID 누락/숫자/배열, 다른 연구 세션의 종료, 충돌, 동시 초기 인덱스 생성, 레거시 인덱스 생성 뒤 원본 내용·트리거 보존의 TDD 부정 회귀 수행. SQLite JSON 함수 호환성은 현재 환경에서 검증했으며, 더 오래된 SQLite/운영 프로세스 환경은 **미검증**.

## 감사 영수증과 검증

- 합성 측정 원본/반복 두 개, 채택되지 않은 중간안 두 개, 최종/반복 두 개의 **총 6개 JSON 수치 영수증**: `quant-t15-evidence-scaling-{baseline,baseline-repeat,optimized,indexed,final-optimized,final-repeat}-20261110.json`.
- 최초 저장 때 수용 기준 딕셔너리의 **정수 키가 JSON 저장에서 문자열 키로 바뀌어**, 메모리 해시와 저장된 JSON 해시가 불일치한 것을 자체 검사로 확인했다. 측정 수치는 그대로 유지하고 파일 저장형의 키를 기준으로 `result_hash`만 재정규화했으며, 벤치마크 스크립트도 **문자열 키로 직렬화 전에 정규화**하도록 수정했다. 여섯 영수증 모두 파일을 다시 읽어 SHA 검증하는 별도 회귀로 통과했다. 이 SHA는 디지털 서명·독립 타임스탬프 증명이 아니다.
