## Final browser-style root cause fixed (2026-10-21 15:40 KST)

A browser can display an unstyled/broken dashboard despite valid HTTP 200 HTML/CSS. The shared DashboardHandler response Content-Security-Policy header said style-src 'unsafe-inline' WITHOUT 'self'. Modern browsers therefore reject the original same-origin linked stylesheet /academic/static/styles.css and /quant-research/static/styles.css. This was the hidden rendering defect missed by server-only checks and mock-DOM tests.

Fixed to style-src 'self' 'unsafe-inline', while retaining default-src 'none', script-src 'self', connect-src 'self', img-src 'self', X-Frame-Options DENY and nginx Basic authentication. Added explicit regression coverage asserting original HTML/CSS routes return a CSP with same-origin style sheets permitted. On the real authenticated local nginx ingress, original CSS GET returned HTTP 200 and a correct Content-Security-Policy; original HTML 200, completion card present, and authenticated public HTTPS HTML 200. Restarted both scoped dashboard backend processes without restarting Moon or modifying research. Native Windows browser screenshot was not obtained; direct HTTP + CSP semantics + Node JS VM + automated tests were verified.
