# S7 2차 — 실제 매매 이벤트 변화 추적 및 개발 구간별 비교

기준일: 2026-10-14. 기존 `S7` 대조실험/연구 메모리 기능을 확장한다. 다음 세대에는 **가설의 결과가 어떻게 발생했는지 관측 가능한 거래 변화와 시간구간별 차이**를 함께 전달한다. 단, 추정된 손익 변화의 인과관계, 재현성, OOS/PIT/실전 유효성은 입증하지 않는다.

## 신규 기능

- `ControlledOutcome.execution_delta`: parent/child `Trade`의 `timestamp + side + symbol`로 관측 체결 **시점이 일치한 건수**, 신규 진입·청산 이벤트 수, 제거 이벤트 수, 같은 시점에서 주문 **수량이 달라진 건수**를 분리한다. 기존 `same_fill_trace`는 수량·비용까지 같을 때만 참이므로, 크기만 달라졌다는 사실을 혼동하지 않게 한다.
- 체결 시점이 변했는지(`execution_timing_changed`)와 두 전략에서 실제 지불한 비용 총액도 보존한다. 이벤트 차이는 최대 16개 증거 샘플로 제공하며, 샘플 외에는 집계된 수를 사용한다. 시점·매수/매도·기록된 수량과 거래비용만 관측하며, 거래를 임의로 다른 포지션과 연결해 **손실 원인을 만들어내지 않는다**.
- `ControlledOutcome.development_windows`: 시장 완료봉의 시계열을 고정된 **4개 연속 부분구간**으로 분할하여 원본/변경 전략의 구간 누적수익률, 구간 최대낙폭, 누적수익률 차이를 측정한다. 각 구간은 바로 앞 구간의 마지막 마감 평가금에서 시작해 구간별 단순 수익률을 재기준화한다. 구간 수익률은 단순 합산할 수 없다. **동일 개발 자료를 잘랐을 뿐 독립 OOS 또는 통계적 유의성 검정이 아니다.**
- 복수 가설을 같은 원본과 비교할 경우 `multiple_comparison_notice=true` 기록. 이 문구는 다중 검정 편향 가능성을 알리는 표시이지, 보정된 p-value나 유효 가설 순위는 아니다.
- 기존 S2 진단 계약, StrategyIR 적용 경계, verified indicator, 다음 봉 체결, 비용 모형, 증거 해시, 코드 실행 금지, 개발 데이터 경계는 변경하지 않는다.
- 이번 대조 보고서 증거 스키마 `s7-paired-development-v2`; 새로운 결과에 이벤트 집계·구간 메트릭이 포함되어 checksum으로 묶인다. **기존 SQLite의 v1 대조 보고서는 변경하거나 재해시하지 않는다.** 이전 보고서가 이미 있으면 기존 `evaluate_algorithm_experiments`의 멱등 조회는 원래 값을 유지하며, 새로운 연구 세대의 보고서에만 v2가 적용된다. 예전 세대를 상세히 다시 보려면 개발 단에서 기존 plan·진단·데이터를 사용해 비영속 재평가할 수 있다.
- MCP 추가 URL/도구 추가 없이 기존 `evaluate_algorithm_experiments` 반환 내용만 확장. **도구 32개 유지**; 서버 URL, OAuth 키·DB, 보호된 코어/실거래 접근 권한 그대로.
