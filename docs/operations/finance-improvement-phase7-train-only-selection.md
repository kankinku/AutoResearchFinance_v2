# T-007 — chronological training-only selection (development)

The GenerationPipeline now independently records `train_only_selection` for every generated candidate cohort. On each chronological walk-forward split it ranks the *already specified* candidate cohort exclusively by training-window total return, deterministically breaks ties by candidate hash, freezes the winner and runs that winner on the subsequent test interval. Prior history warms native causal indicators but cannot generate training-period trades in test equity. Training and test dates, selected candidate hashes, training data hashes, trial counts and test performance are retained in immutable attempt evidence and the local/MCP evaluation response.

`status=EVALUATED` means *development-only precommitted-cohort evaluation*. It does NOT assert that the upstream search itself was trained only on historical folds, or that an independently sealed dataset has been evaluated. `sealed_oos_evaluated` is always false here. The historical per-candidate `validation_folds.selection_applied=false` is deliberately preserved; it must not be confused with the new cohort-selection report. This report does not change champion promotion or award survivor status to a candidate.

External feature series and precomputed features cannot be proved causal by this component, so those cohorts return `UNSUPPORTED_UNVERIFIED_FEATURES` instead of a false successful selection. Native OHLCV feature-input arrays supplied to the pipeline are unused by feature-free native-indicator strategies and do not block them. Later phases must version a full as-of feature-provenance contract and trial lineage before permitting those cohorts.

Validation: `tests/orchestration/test_train_only_selection.py` changes future candles without changing prior fold selection; `tests/orchestration/test_evaluation_runner.py` checks real execution payload and persisted Evidence. Actual independent OOS and corporate-action-adjusted vendor history are still pending.
