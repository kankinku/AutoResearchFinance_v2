# Quant 원시 Nasdaq 수집 안전성 — T0 Task 3 ([4/16], 2026-11-10)

**목표:** Q04/Q09/Q11/Q13/Q17/Q20, V05 사전 입력 무결성. `capture_nasdaq_qqq(...)` 함수 시그니처·보고서 스키마·검증용 해시 불변. 실거래 및 외부 OOS 무관.

## 오류 재현

기존 코드는 세 파일의 사전 존재 여부만 확인한 뒤 raw·Parquet·manifest를 차례로 썼다. 다른 프로세스가 사전 검사 이후 완전한 번들을 저장하면 늦게 실패한 실행의 `except`가 **세 파일 전체를 무조건 삭제**했다. 실패 실행이 해당 파일의 소유자인지 구분하지 못한다.

- RED: 경쟁자가 `fetch_bytes` 호출 중 동일 경로에 유효한 세 파일을 완성시키는 재현 테스트. 기존 구현은 `FileExistsError` 후 승자의 세 파일을 제거한다.
- GREEN: 경쟁자 번들이 그대로 유지되고 `verify_nasdaq_capture()`의 원본 SHA-256·데이터 해시 검사 통과.

## 최소 수정

- 세 출력 대상과 각각 **동일 디렉터리/파일시스템**에서 별개의 고유한 임시 파일을 생성하여 raw·Parquet·manifest를 완성한다.
- Parquet을 **최종 경로 공개 전** 재조회·데이터 해시 검증한다.
- `os.link()`의 존재 시 실패하는 **배타적 하드링크 등록**으로 raw → Parquet → manifest 순서로 최종 공개. manifest는 완료 표시로서 마지막에만 생성된다. 원본/기존 파일은 덮어쓰지 않는다.
- 실패 시 **이번 호출이 성공적으로 링크한 최종 파일만 역순으로 정리**한다. 다른 호출자가 이미 생성한 파일은 삭제하지 않는다. 성공·실패 모두 이번 호출의 임시 파일을 정리한다.
- 새 DB, 워커, OAuth·MCP 변경 및 원시 Nasdaq HTTP 요청 없음. 기존 저장소의 `application/market_data_service.py`도 임시 Parquet과 하드링크 배타적 게시 방식을 사용한다.

## 검증

- 동일 경로 경쟁 **서로 다른 두 OS 프로세스**를 `spawn`으로 시작하여 12회 반복; 매회 1명 성공/1명 충돌, 후속 raw·Parquet·manifest 서명 검증, 임시 파일 누락·유출 검사.
- 사전 검사 후 승자 등록 시나리오, 최종 manifest 등록 시 제3자 파일 충돌, Parquet 쓰기 중단, 이미 존재하는 경로, 원시 바이트 변조, archive·inventory·publisher 연계 회귀 테스트.
- 추가 검증: `pytest tests/research/test_nasdaq_qqq_capture.py` → 16 passed. 수집 관련 테스트/기존 핵심/거버넌스 포함 통합 418 passed.
- 검증은 로컬 임시 디렉터리와 주입된 `fetch_bytes`만 사용했다. **실제 Nasdaq 서비스 요청·시장 자료 수집·새 G1 실제 연구·OOS·주문·운영 배포는 NOT_RUN**.
- 파일시스템이 하드링크를 지원하지 않으면 조용한 덮어쓰기가 아니라 실패한다. 강제 종료 중에는 manifest 없는 미완성 raw/Parquet이 남을 수 있으므로, 최종 번들 확정 여부는 **manifest 및 세 파일의 무결성 검증**으로만 판단한다.
