# Quant Autoresearch — 재정렬 작업 로드맵

작성: 2026-10-14. [결정 기록](../decisions/2026-10-14-autoresearch-interview-20q.md) / [아키텍처 추진안](../architecture/quant-autoresearch-autonomous-research-v2-proposal.md). 개발 기능 완료와 실거래·수익성 인증은 구분한다.

## 현황과 방향 오류

기존 v1 아키텍처는 실전 기반 자산(StrategyIR, 무결성, 백테스트, 매개변수 탐색, 평가, 지식 저장)에 유리하다. 그러나 최근 P0 작업은 QQQ 모멘텀 매개변수·재진입 조건을 **사람이** 반복 개선했다. 이는 제품이 해야 할 연구를 개발자가 대신한 것이다. 2026-10-14 확인한 배치 워커는 초기 연구 지시 뒤 세대별로 LLM을 부르지 않는다. 외부 GPT가 세대별로 새 지시를 줄 수 있는 별도 세션은 존재하지만, 지속 실행 자율 제어기가 아니다.

## 개발 과제와 기능 수락 기준

| 작업 | 우선도 | 범위/재사용 | 완료 판정 |
|---|---|---|---|
| S0 | P0 | 20문답, 코드 인벤토리, 아키텍처/계획 고정 | 20개 질문·사용자 답변을 하나씩 추적 가능, 상태를 구현과 제안으로 구분 |
| S1 | P0 | 기존 계산/체결을 읽기 전용으로 연결하는 `DecisionTrace` | 체결 ID, 직전 완료 봉의 indicator·gate값, 체결가격/비용, 미실행 결정 구분, OOS/변조/미래누출 거부 |
| S2 | P0 | LLM 연구 패킷 (요약 성적·상세 결정 근거·에피소드) | 판정된 값/설명 가설 분리; 원장의 hash/ID에 연결 |
| S3 | P0 | LLM의 AlgorithmPlan→타입드 StrategyIR | 인디케이터 조합·조건·시장상태별 분기·가중치를 안전한 구조로 정의하고 재현 가능 |

| S5 | P1 | N세대/지속 실행·복구 | 10/100세대, 중단/재개·장애 후 멱등성, 요약 보고, 원장 유실 없음 |

| S7 | P1 | 검증 가능한 원인 가설·연구 메모리 | 수정 전후 대조군, 인디케이터 ablation, 기각된 가설을 기록·재활용 |
| S8 | P1 | 탐색/우수 후보 진화/가설 검증 예산 조절 | 동일 예산 무작위 기준과 연구 효율 비교, 중복 후보 감소 검증 |
| S9 | P2 | 논문·설명형 지표 자동 생성·검증 | 출처/라이선스·계산 기준·누출·리소스 검증 후 Registry에 등록 |
| S10 | P2 | 유망 알고리즘 다자산·독립 OOS/순수익 검증 | 고정 선택 과정, 비용/유동성/기업행동/통계 및 검증 타이밍 반영, 주문 승인 별도 |

**우선 구현 순서:** S0 문서 → S1 첫 감사 가능한 거래 근거 → S2·S3 최소 결합 → S4 LLM 분석 포함 2~3세대 통합 증명 → S5 및 S6/S7/S8 확장 → S9/S10. 사용자의 19번 답변 '모두 진행'은 작업 제외를 금지하나, **모든 기능을 완벽히 준비하고서야 루프를 처음 실행하는 방식**도 방지한다. 실제 루프가 작동하는 수직 단면이 최우선.

## 단계별 판정

- **1단계/제품 엔진**: 매 세대 `후보→실행→거래별 근거→수치 평가→LLM 원인 가설→다음 실험` 완주. N세대·지속형/중단·재개 재현. 실패도 정확히 기록. 사용자에게 완료 요약 제공.
- **2단계/자율 개선 효과**: 고정 seed/자산/비용 예산의 랜덤 탐색·기존 규칙과 통제 비교, 특화 성과·가설 적중률·중복·연구 비용 측정. 근거 없이는 '학습했다'고 판정하지 않음.
- **3단계/경제성**: 연구용 공통 자산/기간에서 발굴한 후보를 미사용 시계열/다자산/시장 상태로 검증. PIT, 기업행동, 거래비용/용량, 우연한 발견의 다중검정 문제 반영. 실제 자금 투입은 별도 승인.

## 작업 완료 원칙

- 시험할 데이터와 기준선을 미리 고정해 연구가 사후에 우연히 맞는 데이터만 선택하지 않게 한다.
- `core/data`, `core/backtest`, `core/evaluator`, `core/validation`, `core/costs`, `core/integrity`, Sealed OOS, KIS 주문 권한은 이번 브랜치에서 보호한다.
- 각 기능은 테스트 먼저→코드→대조 실험→전체 pytest/ruff/mypy→GitHub 개발 브랜치 푸시. 과거 v1 아키텍처 문서·복구 브랜치는 변경하지 않는다.
- 테스트·코드가 없고 문서만 있는 항목은 `PROPOSED`로 표시한다. 앞으로 QQQ 전용 모멘텀 재튜닝 자체를 새로운 핵심 개발 단계로 간주하지 않는다.


## 개발 진행 갱신 (2026-10-14)

- **S0:** 인터뷰·아키텍처·로드맵 문서화 및 개발 브랜치 푸시 완료.
- **S1:** 2개 검증 지표 조합에 대한 매매 결정-체결 추적 1차 구현 완료. 모든 일반 StrategyIR 지원은 미완료.
- **S2:** 검증된 감사 패킷을 LLM용 구조화 입력으로 만들고, 출력 가설을 실제 원장 ID·타입드 ResearchIntent·변경된 StrategyIR의 사전검증에 연결하는 1차 기능 구현. 실제 모델 호출·원인 반증 실험·영속 저장은 미완료. [세부 보고](autoresearch-diagnostic-contract-2026-10-14.md).
- **S3~S10:** 추진계획. 작업 완료로 간주하지 않음.


### S3 기능 진행 현황 — 2026-10-14

검증된 복수 학술 인디케이터의 **가중 투표 + 시장 상태별 첫 일치 분기**를 typed `AlgorithmPlan`으로 생성하고 canonical StrategyIR 및 기존 원장/비용 모델에서 실행하는 첫 하위 범위를 구현했다. LLM provider 단일 응답을 스키마 검증해 같은 경로에 연결 가능하며, 미승인 코드·지표·Sealed OOS는 거부한다. [S3 구현 보고](autoresearch-algorithm-plan-s3-2026-10-14.md). 다중 전략/실행 비중 자동 조정/실제 LLM 자율 연구/전체 S3 완료는 아직 미완료로 유지한다.

### S4 1차 체크포인트 실행 — 2026-10-14

기존 S1·S2·S3의 실제 코드를 재사용해 `AcademicCycleService`를 구현했다. 외부 `propose(context)` 제공자가 한 세대에 **AlgorithmPlan 1회 + DiagnosticResponse 1회**의 구조화 응답을 준다면, 실행·진단·체인형 증거 저장을 완료하고 이전 세대 성과·가설을 다음 알고리즘 설계 요청에 전달한다. 동일 논리와 동일 매매 신호의 중복 세대는 거부하며 중간 오류는 인터럽트 상태로 보존한다. [자세한 구현 보고](autoresearch-s4-cycle-2026-10-14.md).

**현 단계 판정:** 실제 QQQ 자료에 대한 **mock provider 3세대 수직 통합 확인**. 실제 인증 GPT 모델 호출, 모델 비용·실패 검증 및 지속형 실행(S5), 특정 가설에 결박된 대조 실험 자동 실행(S7)은 미완료다. 따라서 20문답 20번 기준의 1단계 제품 엔진 전체 완료로 판정하지 않는다.

### S4 2차 — 기존 MCP URL을 유지하는 실제 GPT 체크포인트 계약

[기존 Quant MCP URL 유지형 ChatGPT 연구 워크플로](autoresearch-s4-mcp-bridge-stable-url-2026-10-14.md)를 추가한다. 인증된 ChatGPT가 같은 MCP URL에 새 도구로 AlgorithmPlan을 보내고 서버의 계측 결과를 받은 뒤 DiagnosticResponse를 제출해 세대가 완료된다. 이는 서버 내 LLM 프로바이더 도입을 금지하는 기존 정책과 양립한다. 운영 전환이 성공했더라도 ChatGPT 앱 도구 캐시가 갱신되었다는 것은 별도로 실제 호출 확인해야 하며, 완전 무인 지속 연구/LLM 학습 효과·독립 수익은 아직 미검증.

### S5 1차 중단·보고·복구 — 2026-10-14

[체크포인트 운영 개선](autoresearch-s5-checkpoint-operations-2026-10-14.md): 안전한 취소, 완료된 Evidence 보존, 최종 수치 요약, gateway/core 상태 불일치에 대한 명시적 복구와 새 MCP 도구 2개를 개발 브랜치에 추가했다. 아직 실제 지속형/백그라운드 연구나 10~100세대 실모델 재현성 검증은 완료하지 않았다. 기존 URL 및 OAuth 등록은 그대로 유지한다.

### S7 1차 — 실제 대조 백테스트 / 다음 연구에 관측값 회신

[통제 실험 및 연구 기억 연결](autoresearch-s7-controlled-experiments-2026-10-14.md): 기존 LLM 원인 가설을 단순히 저장하는 대신 parent와 child를 동일 개발 구간·동일 자본·동일 비용 모델에서 **실제 실행**하고, 동일 거래이면 변화 없음으로 기록하고 예측 방향과 결과를 구분하는 S7 첫 기능을 구현했다. 세대별 실험 결과는 별도 SQLite 증거로 멱등 보존하며 다음 세대의 GPT 입력에 제공한다. 검증은 재사용 DEVELOPMENT NON-PIT에 한정되어 인과 입증, 독립 OOS, 실전수익 증명이나 전체 S7 완료가 아니다.

### S7 2차 — 거래 이벤트·기간별 성과 귀속 (2026-10-14)

[거래별 차이/4구간 성과 증거](autoresearch-s7-execution-attribution-v2-2026-10-14.md): 기존 개발 비교 결과에 **신규/제거/수량만 변경한 체결 이벤트**와 동일 개발 자료를 고정 4구간으로 나눈 성과 변화를 추가했다. 기존 저장된 v1 보고서를 변경하지 않고 새 v2 실험에만 반영한다. 운영에서 저장했던 실제 QQQ 두 세대의 **읽기 전용 v2 재계산** 결과는 필터 제거가 69건 체결 모두 동일, 투자비중 70% 변경은 53건 전부 체결 시점 유지·수량만 변경으로 나타났다. 표본 외 유효성·인과 검증·통계적 신뢰성은 이 개발 구간 비교만으로 확인되지 않는다.

### S6 1차 — 버전 고정 지표 카탈로그 및 새 4종 이진 진입 후보

### 2026-10-15 — 발행사 배당 교차검증 및 수집시점별 가격 수정 비교

[상세 근거 및 한계](autoresearch-issuer-dividend-revisions-2026-10-15.md): Invesco QQQ 공식 분배금 7건(2020~2025)과 Tiingo raw/조정 종가 인자의 배당락일 변화로 역산한 금액 7건 **전부 일치**(각 금액 0.0001 달러 이내). 이는 선택한 현금 배당의 외부 발행사 점검이며, 분할·모든 배당·과거 as-of 가격 전체가 입증된 것은 아니다. 발행사 자료를 해시 고정한 `issuer_distributions.py` 검증을 관리 시세 감사에 통합하고, 서로 다른 실제 수집시점/동일 공급자·종목·정책의 두 과거 시세 데이터에서 OHLCV 수정 여부를 측정할 수 있는 `snapshot_revisions.py`를 추가했다. 새 시점 비교 기능은 내부 감사 서비스의 선택형 매개변수로 제공하고, 새 MCP 도구를 요구하지 않는다. 현재 네 보존 Tiingo 데이터 파일은 서버 상태 DB에 원본 해시로 신규 pin 완료했으며 이후 파일 변경 감지에만 사용한다. 실제 겹치는 두 역사적 수집본은 없으므로 **관측된 가격 수정 이력은 아직 없음/미확인**.
