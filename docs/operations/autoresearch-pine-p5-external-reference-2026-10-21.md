## Purpose, current status

Prior BOSWaves and Shaakuni semantic adapters passed synthetic regression tests but have **no actual independent TradingView reference export**. An adapter-generated copy of its own output cannot prove parity. This work implements a read-only, fail-closed reference CSV comparison path without operational feature promotion or real orders.

## Input / output contract

- Code: research/pine_import/p5_reference_compare.py
- Inputs: DEVELOPMENT-only US equity daily MarketDataSet, metadata manifest and UTF-8 CSV bytes.
- Manifest fields: indicator (boswaves/shaakuni), original_upload_sha256 (pinned user-upload archive SHA, NOT raw reconstructed .pine hash), dataset_hash, reference_csv_sha256, claimed_export_origin (untrusted claim).
- CSV mandatory base columns: timestamp,open,high,low,close.
- BOSWaves fields: alma,deviation,atr,slope,trend,flip,conviction,ribbon_edge,ribbon_mid,stopped_now,new_target_hits.
- Shaakuni fields: atr,pdh,pdl,pwh,pwl,created_bull,created_bear,fresh_bull,fresh_bear,mitigated.
- All timestamps: timezone-aware ISO-8601; market and export must refer to the **same exact bar instant**. If chart CSV time is the opening of the bar but dataset time means closing, investigate and record the difference, do NOT silently shift data.
- Exact headers, aligned rows, monotonic time, OHLC, source archive/hash, development dataset/hash, CSV SHA-256, finite numbers and bounded comparison tolerance are required. Missing values may be blank/na only, never nan/infinite. Missing/duplicate columns, missing bars and sealed OOS fail closed.
- Return mismatches with counts and first 30 differences. Event/boolean/count values are exact integers. Numeric tolerance is tightly bounded.
- **Regardless of numeric match**, reported state is NUMERIC_MATCH_ONLY_UNAUTHENTICATED or MISMATCH; independent_tradingview_origin_authenticated=False, full_pine_parity_approved=False, operational_feature_promotion_allowed=False. A manifest can lie about TradingView origin: this code cannot authenticate source or order-filling behaviour.

## Actual external comparison procedure

1. Obtain the original licensed Pine v6 script, its original upload hash, script identity/version and trading parameters. Source remains outside Git as required. Preserve MPL-2.0 attribution where relevant.
2. In an independently controlled TradingView chart, add output-only observation channels to a verification copy of the **same source** without modifying entry/exit logic. Record chart symbol, market data adjustments, timezone, session, tick size, date range, timeframe, Pine script version and an exact script source hash.
3. Export source chart data and preserve its raw CSV and its checksum. If necessary normalize to the required ISO-8601/column contract in a **separate auditable file**, documenting all transformations. Manifest CSV hash refers to normalized comparison bytes.
4. Compare identical dataset bars using compare_pine_reference. Investigate discrepancies and do not cherry-pick favourable rows or silently fill absent data.
5. UI drawings, weekend/live timenow panels, stateful alerts and strategy broker fills require independent reference coverage beyond this numeric adapter. Matching a synthetic or unauthenticated file does **not** meet P5.
6. Following independent original-source authentication, scope-appropriate TradingView output and trading semantics parity, proceed by separate acceptance to optional typed P6 FeatureRegistry registration and finally **real GPT research / S7 diagnosis / next generation inheritance (P7)**.
