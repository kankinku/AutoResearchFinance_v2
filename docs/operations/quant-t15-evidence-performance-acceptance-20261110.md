# Quant [16/16] T15 원장 성능 수용 기준 (실측 전 잠금)

**기록:** 2026-11-10 KST · **단계:** Task 15 · **상태:** PREDECLARED_NOT_YET_MEASURED

## 보호 범위
- 사용자 승인 16단계의 조건부 성능 최적화. 신규 실제 시세/구 G150의 원본/원격 Quant MCP/주문/봉인 OOS를 읽거나 쓰지 않는다.
- 측정은 `tempfile.TemporaryDirectory`에서 만든 별도 **합성 SQLite**만 사용. 원본 `EvidenceStore` API 및 스키마/이벤트 체크섬·불변 트리거 유지.
- 원본 20문답, 승인 아키텍처, 주문 OFF, 32 MCP/OAuth, 새 G1 연구와 과거 150세대 활성 분리 정책 불변.
- 새로운 인덱스·캐시·대형 서비스 파일 분리는 **측정 결과가 수용 기준을 넘어선 경우에만**, 동등성·무결성 증명이 확보된 최소 변경으로 한정.

## 측정 방법과 사전 정한 *진단용* 목표
기준 샘플 규모는 **150 / 1,000 / 10,000개 이벤트**. 10,000번 실제 연속 `append()`의 O(n²) 초기화 비용을 피하기 위해, 합성 유효 이벤트를 단일 SQLite 트랜잭션으로 미리 채워 두고 해당 크기에서 기존 공개 `append()` 11회와 `events()` 5회를 측정한다. **10,000회 연속 append 처리량을 재현했다고 주장하지 않는다.**

| 샘플 | 증분 append p95 진단 기준 | 전체 events() 읽기 p95 기준 |
|---|---:|---:|
| 150개 | 30 ms | 70 ms |
| 1,000개 | 60 ms | 150 ms |
| 10,000개 | 100 ms | 800 ms |

- 추가 진단: 10,000개 전체 읽기의 파이썬 추적 피크 메모리 **128 MiB 이하**(tracemalloc), SQLite `integrity_check`, 이벤트별 SHA256 체크섬, **UPDATE/DELETE 금지 트리거**, 충돌 시 롤백·기존 이벤트 보존, 쓰기 잠금 150 ms 동시성 대기 후 정상 복귀.
- `p95`는 측정 11/5회의 최근접순위 95백분위(최대값에 가까워 노이즈에 민감)이며 **실험 환경 한정**. OS 스케줄러·WSL/NTFS 지연과 반복 수를 함께 기록. 오차가 임계값 근처면 한 번 더 반복하고, 정식 운영 SLO로 주장하지 않는다.
- 이 표는 **검증 전에 설정한 연구용 공학 목표이며 사용자/운영 SLA로 승인받은 수치가 아니다**. 반드시 기준 버전·머신·파이썬·SQLite·동일 합성 payload/반복 횟수/데이터 원본 SHA·실측 로그를 같이 제시한다.
