# 백테스트 성과 중심 대시보드 설계

## 목표

백테스트 화면의 기본 단위를 개별 실행이 아니라 세대별 최고 후보로 바꾼다. 사용자는 화면을 열었을 때 현재 탐색 세대, 전략과 QQQ의 성과, 안정성, 사용 인디케이터와 입력 자료를 즉시 확인할 수 있어야 한다.

## 화면 원칙

- 첫 화면은 `현재 N / 요청 M세대`, 실행 상태, 현재 단계 경과시간을 고정적으로 보여준다.
- 핵심 KPI는 전략 연복리, QQQ 연복리, QQQ 대비, 누적 수익률, 최대 낙폭, Sharpe, 거래수, 위험 준수율이다.
- 성과 추이는 세대별 최고 후보를 기준으로 전략 연복리·QQQ 연복리·QQQ 대비·점수를 함께 표시한다.
- 세대 선택지는 실행 ID가 아닌 `N세대 · 최고 후보`로 표시한다.
- 선택한 세대의 인디케이터, 입력 자료, 시간봉, lag/lookback, 파라미터, 제안 사유, 연도별 성과를 본문에 둔다.
- 실행 ID, 전략/데이터 해시, 검증 폴드, gate 원문, 변경 작업은 진단용 접이식 영역에 둔다.
- 값이 없는 경우 `아직 평가 전`, `원장에 해당 지표 없음`, `벤치마크 데이터 미연결`을 구분해서 표시한다.

## 데이터 경계

`state/test-records.jsonl`과 `state/system/autoresearch.json`을 읽기 전용으로 사용한다. 기존 `TestRecord`의 수치와 lineage를 재사용하고, 세대 요약은 API 응답 시점에 생성한다. 주문 API나 실전투자 경로는 이 화면에서 호출하지 않는다.

## 후보 선택

세대별 후보 중 `REJECT`가 아닌 후보를 우선하고, 그 안에서 점수가 가장 높은 후보를 선택한다. 해당 세대에 통과 후보가 없으면 전체 후보 중 점수가 가장 높은 후보를 표시한다. 이 규칙은 기존 Streamlit 성과 화면과 일치시켜 두 화면의 “최고 후보” 의미가 달라지지 않도록 한다.

## 실시간 연구 연결

`state/system/autoresearch.json`의 요청 세대수, 완료 세대수, 현재 세대, 현재 단계, 단계 시작 시각, 상태를 `research` 객체로 노출한다. 브라우저는 15초마다 API를 읽고, 현재 단계 경과시간은 마지막 상태 파일을 기준으로 계산한다.
