# MCP 전체 시스템 오케스트레이터 설계

## 목표

Codex Desktop에서 한 번의 승인된 MCP 명령으로 로컬 연구 시스템의 필수 조건을
점검하고, 문제가 있으면 실행하지 않은 채 복구 조치를 반환한다. 조건이 통과하면
대시보드, 연구 방향 탐지 워커, Docker 격리 백테스트 워커를 시작하고 작업 상태를
조회할 수 있게 한다.

## 범위

- `check_system`: 실행 전제조건 점검
- `start_system`: 점검 통과 시 대시보드·연구 워커·Docker 백테스트 워커 기동
- `get_system_status`: 컴포넌트별 상태 조회
- `stop_system`: 기동한 로컬 컴포넌트와 Docker 컨테이너 중지
- 기존 `run_evaluation`을 공통 평가 실행기로 추출해 CLI·MCP·워커에서 공유
- Docker 격리 백테스트용 이미지 빌드 파일과 민감파일 제외 규칙

## 안전 경계

- 유효 모드는 항상 `paper`, 주문 기능은 호출하지 않는다.
- 연구·백테스트 입력은 프로젝트 루트 아래의 허용된 전략 파일과 Parquet만 사용한다.
- `sealed_oos` 데이터는 사전점검과 평가 실행 모두에서 거부한다.
- Docker 백테스트 컨테이너는 네트워크를 끄고, capability를 제거하고, 루트 파일시스템을
  읽기 전용으로 마운트한다. 결과 상태 디렉터리만 쓰기 가능하다.
- MCP 서버는 임의 셸 명령이나 파일 경로를 받지 않고 허용된 입력·이미지만 받는다.
- KIS 계좌 조회와 주문·실전투자는 전체 시스템 기동 조건에 포함하지 않는다.

## 실행 흐름

1. Codex Desktop이 등록된 stdio MCP 서버에 `check_system` 또는 `start_system`을 호출한다.
2. Python·상태·전략·Parquet 메타데이터·Paper-only·Docker 엔진·Docker 이미지·대시보드
   포트를 확인한다.
3. 필수 검사에 실패하면 `BLOCKED`와 각 실패 항목의 조치 명령을 반환한다.
4. 통과하면 대시보드를 로컬 프로세스로, 전략 탐지를 로컬 Codex CLI 워커로, 백테스트를
   네트워크 차단 Docker 워커로 병렬 기동한다.
5. 컴포넌트 상태와 작업 결과는 `state/system/` 및 기존 `state/test-records.jsonl`에
   비밀정보 없이 기록한다.

## 수용 기준

- Docker Desktop이 꺼져 있거나 이미지가 없으면 프로세스를 시작하지 않고 조치 목록을
  반환한다.
- 전략 파일·Parquet 파일·데이터 메타데이터가 없거나 OOS 봉인 영역이면 시작하지 않는다.
- Paper-only가 아니면 시작하지 않는다.
- 모든 필수 조건이 통과하면 대시보드·연구 워커·백테스트 워커가 동시에 시작된다.
- MCP 도구 목록에 시스템 점검·기동·상태·중지가 나타난다.
- 기존 전체 품질 검사와 MCP 안전 경계 테스트가 통과한다.

## 미포함

- Codex Desktop 대화 자체를 MCP 서버가 재사용하는 기능
- KIS 주문 또는 실전 계좌 기능
- 원장에 저장되지 않은 equity curve를 추정해 생성하는 기능
- Docker 이미지가 없는 환경에서 네트워크를 사용해 자동 빌드하는 기능
