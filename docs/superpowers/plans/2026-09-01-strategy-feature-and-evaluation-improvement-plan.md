# 전략 특성·외부 데이터·평가 확장 개선 계획

작성일: 2026-09-01
기준 시스템: Quant Autoresearch Harness v1.0 구현 작업본
목적: 지금까지의 인터뷰에서 확정한 투자 범위, 운용 방식, LLM의 데이터 선택, 신규 지표 등록, 전략 평가 개선을 기존 아키텍처에 누락 없이 반영한다.

## 1. 계획의 결론

현재 시스템은 지표 조합으로 매수·매도 신호를 탐색하고, 후보 전략을 백테스트·강건성 평가·OOS 검증·메모리 저장하는 기반을 갖추고 있다.

개선의 핵심은 이를 **LLM이 선택하는 다중 자산·거시환경 특성 기반 전략 연구 시스템**으로 확장하는 것이다.

LLM은 다음을 선택하거나 제안할 수 있다.

- 대상 종목의 가격·거래량 기반 지표
- VIX, 금, DXY, 주요 지수, 섹터 ETF
- 미국·일본·한국의 2년물·10년물 금리
- 금리차, 변화율, 이동평균, 변동성, 국면 등 파생 특성
- 여러 데이터 간의 비교·상관·조건 조합
- 특성별 기간, 임계값, 지연값, 시장국면 조건

이 데이터들은 전략에 고정 필수로 들어가지 않는다. 모든 데이터는 후보군으로 등록하고, 각 전략에서 LLM이 취사선택한다. 실제 계산과 평가는 로컬 결정론적 엔진이 수행한다.

기존 평가 항목과 Funnel 통과 구조는 그대로 유지한다. 여기에 전략의 절대 수익성 및 동일 기간 Nasdaq 벤치마크 비교를 추가한다.

## 2. 인터뷰에서 확정된 요구사항

### 2.1 운용 모드

- 모의투자와 실전투자 두 모드를 제공한다.
- 사용자가 Codex Desktop에서 자연어로 모드를 지정한다.
- 시스템은 모드를 자율적으로 변경하지 않는다.
- 실전 모드 선택만으로 주문이 실행되어서는 안 된다.
- 실전 주문은 별도의 명시적 인간 승인과 독립적인 안전 게이트를 거친다.
- 실전 계좌와 모의 계좌의 인증, 세션, 통화, 수수료, 거래 규칙을 분리한다.

### 2.2 거래 대상

- 초기 거래 유니버스는 미국 상장 개별 주식과 미국 상장 ETF만 사용한다.
- 사용자가 지정한 종목 목록만 사용한다.
- 자동 종목 발굴·스크리닝은 초기 범위에서 제외하고 나중에 별도 기능으로 추가한다.
- 사용자 목록이 변경될 때만 유니버스가 변경된다.
- 한국·일본 종목을 거래 대상으로 추가하는 것은 현재 범위가 아니다.
- 다만 미국 주식·ETF 전략의 외부 설명 변수로 미국·일본·한국 거시금리를 사용할 수 있다.

### 2.3 시간 기준과 주문 시점

- 기본 전략 기준은 일봉이다.
- 다른 봉은 보조 데이터로 사용할 수 있다.
- 일봉과 보조 봉은 거래일·타임존·가용 시점을 정렬한다.
- 미래 데이터가 신호에 유입되지 않도록 모든 입력에 지연과 기준 시점을 기록한다.
- 일봉 종가가 확정된 뒤 신호를 계산한다.
- 신호는 다음 거래일 시가 주문으로 변환한다.
- 미국 시장의 거래일·타임존·휴장일을 기준으로 처리한다.

### 2.4 전략이 관리하는 항목

전략이 다음 항목을 선언하고, 평가 데이터로 함께 기록한다.

- 매수·매도 조건
- 종목별 배분
- 포지션 크기
- 동시 보유 종목 수
- 매수 금액
- 위험 감수율
- 손실 허용도
- 일일 손실 발생 시 행동
- 손절·익절·트레일링 조건

전략이 위험 특성을 관리하더라도, API 이상·중복 주문·비정상 가격·급격한 손실을 막는 변경 불가능한 시스템 긴급 차단 장치는 전략 밖에 둔다. 전략은 이 장치를 변경하거나 우회할 수 없다.

### 2.5 LLM의 역할

- LLM은 지표, 외부 데이터, 기간, 조건 조합, 새 특성을 연구 후보로 제안한다.
- LLM은 자유 형식 Python 패치나 평가기 변경을 직접 실행하지 않는다.
- LLM의 제안은 Strategy IR와 FeatureSpec으로 변환·검증한다.
- 실제 계산, 백테스트, 통계 평가, OOS 접근 제어는 로컬 엔진이 담당한다.
- Codex Desktop은 운영자가 연구 의도를 전달하고 결과를 검토하는 인터페이스로 사용한다.

### 2.6 새 지표·새 특성 등록

LLM이 현재 없는 지표나 특성을 제안할 수 있다.

1. LLM이 새 특성의 계산식과 필요한 데이터, 시점, 기간, 결측 처리, 예상 목적을 제안한다.
2. 시스템이 FeatureSpec 스키마와 보안·자원 제한을 검증한다.
3. Codex Desktop 기반 구현 작업이 격리된 개발 환경에서 수행된다.
4. 단위 테스트, 기준값 테스트, 과거 데이터 계산 테스트를 실행한다.
5. 미래 데이터 누수, 거래일 정렬, 결측값 처리, 동일 입력 재현성을 검사한다.
6. 모든 검사를 통과하면 버전·해시·출처를 부여해 Feature Registry에 등록한다.
7. 등록된 특성은 이후 전략 후보 생성에서 선택할 수 있다.
8. 검증 실패 특성은 격리 보관하며 전략 실행·실전 배포에서 사용할 수 없다.

등록은 “실험에서 사용할 수 있음”을 의미할 뿐, 자동으로 전략에 포함되거나 실전 주문에 사용됨을 의미하지 않는다.

### 2.7 평가 기준

기존 평가 항목과 통과 구조를 모두 유지한다.

기존 항목:

- Fast·Full 평가
- Walk-forward 검증
- Validation·Sealed OOS 검증
- 강건성·민감도 분석
- 시장국면별 분석
- CSCV·CPCV
- DSR·PBO 등 통계적 과적합 점검
- 거래비용·슬리피지 민감도
- 거래 횟수·회전율
- 전략 복잡도·과적합 검사
- 기존 Funnel 및 Survivor·Near Miss·Reject·Champion 상태 전이

추가 항목:

- 비용 차감 후 절대 수익률
- 동일 기간 QQQ 총수익률
- 동일 기간 Nasdaq Composite 수익률
- 전략과 벤치마크의 CAGR 차이
- 전략의 초과수익률
- 전략이 벤치마크를 앞선 평가 구간 비율
- 외부 특성 제거 전·후 성과 차이
- 선택된 특성별 한계 기여도와 안정성

평가 우선순위는 수익성을 1순위로 둔다. 다른 지표가 양호하더라도 절대 수익성이 낮은 전략은 높은 등급을 받지 못한다. 다만 기존 위험·강건성·OOS 평가를 제거하거나 수익률 하나만으로 Champion을 결정하지 않는다.

QQQ 비교는 주 벤치마크로 추가하고, Nasdaq Composite는 참고 벤치마크로 기록한다. 기존 평가 기간과 분할은 변경하지 않고, 각 기존 평가 구간에 벤치마크 결과를 추가한다.

## 3. 현재 구현 상태와 개선 격차

### 3.1 이미 존재하는 기반

- Strategy IR 스키마·파서·검증기·컴파일러
- 지표·조건 기반 후보 전략 생성
- 구조 탐색 및 파라미터 탐색
- Grid·Random·Bayesian 탐색
- 데이터 계약과 개발·검증·Sealed OOS 구역 개념
- 비용 모델을 포함한 백테스트
- Fast·Full 평가, 강건성, Walk-forward, Funnel
- CSCV·CPCV·Pareto·민감도·국면 분석 모듈
- Frontier·Champion·Rescue Pool·Knowledge Memory
- Docker 기반 연구 워커 격리
- 연구 Director의 구조화된 Intent 계약
- KIS 연구·모의·실전 승인 경계의 기본 구조
- `.env` 비추적 및 `.env.example` 제공

### 3.2 이번 개선에서 반드시 보완할 부분

1. 현재 데이터 계약은 단일 MarketDataSet의 OHLCV 중심이므로 여러 종목과 거시 시계열을 함께 표현할 수 있어야 한다.
2. 현재 백테스트 계산기는 SMA·EMA·RSI 중심이므로 Registry에 선언된 MACD·ATR·ADX·Bollinger·거래량 돌파·변동성·국면 특성을 실제 계산기로 보강해야 한다.
3. VIX·금·DXY·지수·섹터 ETF·미국·일본·한국 2년물·10년물의 입력 정의와 공급자 연결이 필요하다.
4. 다중 자산·다중 시간봉의 as-of 정렬과 미래 데이터 누수 검사가 필요하다.
5. LLM이 FeatureSpec을 제안하고 구현 성공 후 Registry에 자동 등록하는 생명주기가 필요하다.
6. `RiskConfig`에 위험 감수율·손실 허용도·일일 손실 행동을 전략 평가 데이터로 남길 명시적 필드가 필요하다.
7. QQQ 총수익률과 Nasdaq Composite의 동일 구간 수익률 계산기가 필요하다.
8. 외부 특성별 제거 실험과 한계 기여도 분석이 필요하다.
9. KIS 연구 어댑터의 현재 실데이터 조회 공백을 실제 읽기 전용 데이터 공급자 설정으로 보완해야 한다.
10. Codex Desktop의 자연어 운영 요청을 Research Intent와 모드·승인 상태에 연결하는 운영 어댑터가 필요하다.
11. 실제 실전 연결 전에는 노출된 기존 키를 폐기·재발급해야 한다. 현재 저장된 `.env`의 비밀값은 출력·커밋·로그 기록 대상이 아니다.

```text
        Strategy IR / 후보 생성 / 캐시
                │
                ▼
  Fast → Full → Robustness → Validation/OOS
                │

        Paper → Live Gate → KIS
```

## 5. 단계별 개선 실행 계획

### 단계 0. 사전 조건과 비밀정보 정리

**목표:** 실제 데이터·계좌 연결 전에 보안과 실행 경계를 확정한다.

- `.env`를 계속 Git 추적에서 제외한다.
- `.env.example`에는 실제 키가 아닌 변수명과 예시 URL만 둔다.
- 로그·실험 결과·LLM Context·메모리에 비밀값이 포함되지 않는지 검사한다.
- 대화에 노출된 실전·모의 키는 폐기하고 새 키를 발급한다.
- 실전 키와 모의 키를 별도 변수·별도 프로세스·별도 권한으로 관리한다.
- 데이터 공급자, 거래 캘린더, 환율·통화, QQQ 배당 처리 기준을 설정 파일로 명시한다.
- Codex Desktop은 연구 의도와 승인 인터페이스로 사용하고, 주문 권한은 별도 프로세스에 둔다.

**완료 조건:** secret scan 통과, `.env` 비추적 확인, 재발급된 키 없이는 실전 연결이 DENY, 연구 프로세스에서 주문 모듈 import 불가.

### 단계 1. 다중 자산 데이터 계약 확장

**목표:** 미국 대상 종목과 외부 거시 시계열을 같은 실험에서 안전하게 참조한다.

구현 대상:

- `InstrumentRef`: 시장, 심볼, 자산 유형, 통화, 거래 캘린더
- `SeriesRef`: VIX·금·DXY·지수·ETF·금리 시계열 식별자
- `TimeFrame`: 일봉 및 보조 시간봉
- `Availability`: 관측 시각, 확정 시각, 시장 사용 가능 시각
- `AlignedObservation`: 기준 시점, 원천 시점, lag, 결측 상태, 데이터 버전
- `MacroSeriesConfig`: 미국·일본·한국 2년물·10년물 금리
- 데이터 원천·조정 방식·단위·타임존·결측 정책·해시

금리 데이터는 사용 가능한 후보로만 제공한다. 어떤 전략에도 자동으로 넣지 않는다.

**검증:** 휴장일 불일치, 시차, 중복 시점, 발표 후 확정 시점, 결측 구간, 보정 데이터, 미래 관측 참조를 합성 데이터로 검증한다.

### 단계 2. Feature Registry와 특성 계산기 확장

**목표:** LLM이 선택할 수 있는 특성 공간을 넓히되, 실행 가능한 특성만 허용한다.

각 FeatureSpec은 최소한 다음을 가진다.

- 고유 ID와 버전
- 특성 계열
- 입력 SeriesRef 목록
- 기간·시간봉·지연값
- 계산식과 출력 타입
- 결측·초기 구간 처리
- 시장 사용 가능 시점
- 계산 비용과 자원 제한
- 기준값 테스트 벡터
- 구현·테스트·등록 해시
- 설명과 예상 경제적 의미

우선 구현할 특성군:

- SMA·EMA·RSI
- MACD·ATR·ADX
- Bollinger Bands
- 거래량 돌파·52주 고점·변동성 필터
- 추세·평균회귀·위험선호/회피 국면
- VIX 수준·변화·백분위
- 금·DXY·지수·섹터 ETF의 수익률·추세·상대강도
- 미국·일본·한국 2년물·10년물 금리의 수준·변화·기간별 통계
- 국가별 금리 간 스프레드와 변화
- 대상 종목과 외부 자산의 상대수익률·롤링 상관·베타

상관관계는 신호의 단독 근거로 강제하지 않는다. LLM이 선택할 수 있는 조건 중 하나이며, 모든 상관계수는 계산 시점 이전 데이터만 사용한다.

### 단계 3. FeatureSpec 기반 LLM 제안 및 등록 생명주기

**목표:** LLM이 새 조건을 확장하되 코어 계산기와 평가기를 오염시키지 않는다.

구현 흐름:

1. Context Builder가 Registry 목록, 계산 가능 범위, 실패한 특성, 특성별 검증 요약만 제공한다.
2. LLM은 `FeatureProposal` 또는 `ResearchIntent`를 JSON Schema로 반환한다.
3. 제안에는 수식, 입력, 시간봉, lag, 결측 처리, 예상 비용, 목적, 검증 벡터를 포함한다.
4. validator가 임의 import, 파일·네트워크 접근, 주문 API, 보호 모듈 수정, 미선언 입력을 거부한다.
5. Codex Desktop 작업은 격리된 브랜치·워커에서 구현한다.
6. 테스트 통과 후에만 Registry 버전을 생성한다.
7. Registry 등록 후에도 후보 전략 백테스트와 Funnel을 통과해야 Frontier·Champion에 들어간다.

**등록 통과 게이트:**

- 스키마 검증 PASS
- 단위 테스트 PASS
- 기준값·참조 벡터 테스트 PASS
- 과거 데이터 계산 테스트 PASS
- 미래 데이터 누수 검사 PASS
- 거래일·타임존·as-of 정렬 PASS
- 결측·초기 구간 정책 PASS
- 동일 입력 재현성 PASS
- 자원·실행시간 제한 PASS
- 비밀정보·임의 코드·주문 권한 검사 PASS

실패 제안은 `QUARANTINED` 상태로 남기고, 실패 원인과 재시도 가능 조건만 Knowledge Memory에 기록한다.

### 단계 4. Strategy IR과 위험·배분 표현 확장

**목표:** 선택된 외부 특성과 전략의 위험 행동을 하나의 재현 가능한 IR로 보존한다.

확장 대상:

- `FeatureRef`와 다중 입력 조건
- 교차 자산 비교·스프레드·상관 조건
- 보조 시간봉 참조와 명시적 lag
- Feature Registry 버전·해시
- 전략 위험 감수율
- 손실 허용도
- 일일 손실 행동
- 종목·섹터·전체 포트폴리오 배분
- 동시 보유 수와 포지션 크기
- 다음 거래일 시가 실행 정책

위험 관련 값은 전략마다 다를 수 있고 평가에 포함한다. 시스템 긴급 차단 기준은 별도 보호 계약으로 유지한다.

### 단계 5. 백테스트·실험 실행 확장

**목표:** 다중 자산 특성 사용 전략도 기존의 재현성·격리·캐시 규칙을 그대로 따른다.

- 각 실험 해시에 대상 종목 목록, 외부 SeriesRef, FeatureSpec 버전, 데이터 버전, lag 정책을 포함한다.
- 공유 데이터는 읽기 전용으로 마운트한다.
- 실험 결과는 고유한 출력 디렉터리에 저장한다.
- 동일한 IR·데이터·평가기·비용 모델·시드이면 캐시를 사용한다.
- 외부 특성의 누락 또는 사용 가능 시점 위반은 결과를 만들지 않고 명시적 실패로 기록한다.
- 시장별 캘린더와 다음 거래일 시가 주문 변환을 실험 결과에 기록한다.
- 보조 시간봉은 일봉 신호 시점 이전에 확정된 값만 사용한다.

### 단계 6. 기존 평가 유지 + 수익성·벤치마크 확장

**목표:** 현재 평가 체계를 보존하면서 전략의 실제 투자 가치를 추가 측정한다.

기존 Funnel은 삭제·축소·대체하지 않는다. 현재 Fast·Full·Robustness·Validation·Promotion 흐름과 기존 통계 검사를 모두 유지한다.

추가 계산:

- 비용·슬리피지 차감 후 절대수익률
- 동일 기간 QQQ 총수익률
- 동일 기간 Nasdaq Composite 수익률
- QQQ 대비 초과수익률
- Nasdaq Composite 대비 초과수익률
- 전략·벤치마크의 CAGR 차이
- 각 Fast·Full·Walk-forward·Validation·OOS 구간별 비교
- 벤치마크 초과 구간 비율
- 외부 특성 제거 실험 결과
- 특성별 한계 기여도와 기여도 안정성

점수 구조:

1. 절대 수익성 중요도를 가장 높게 둔다.
2. 벤치마크 대비 초과수익률은 기존 항목에 추가한다.
3. 위험조정수익률·낙폭·일일 손실·거래비용·안정성은 기존 기준대로 함께 평가한다.
4. 절대 수익성이 낮은 전략이 위험 지표만 좋아서 상위 전략이 되지 않도록 한다.
5. QQQ 또는 Nasdaq 비교 결과는 기존 평가 결과를 대체하지 않고 추가 근거로 기록한다.

특성 기여도는 최소한 다음 세 가지를 비교한다.

- 해당 특성을 사용하지 않은 동일 구조 전략
- 해당 특성을 사용한 전략
- 해당 특성의 시점·값을 통제된 방식으로 제거한 전략

### 단계 7. Memory·Analyzer·LLM Context 확장

**목표:** LLM이 단순히 수익률만 보고 반복하지 않고, 어떤 특성이 어떤 조건에서 기여했는지 학습하도록 한다.

Knowledge Memory에 저장할 항목:

- 특성 ID·버전·해시
- 사용된 전략 계열
- 대상 종목군과 시장국면
- 절대 성과와 QQQ/Nasdaq 상대 성과
- 제거 실험 결과
- 기간·lag·임계값 민감도
- 반복 검증 횟수와 증거 수준
- 실패 게이트와 재사용 가능성
- 상관·중복 특성 관계

LLM Context에는 원시 시장 데이터·Sealed OOS·비밀값·전체 로그를 넣지 않는다. 압축된 통계와 해시·ID만 전달한다.

### 단계 8. 사용자 모드·Codex Desktop 운영 연결

**목표:** 사용자가 자연어로 연구·모의·실전 모드를 지정하되, 위험한 상태 변경은 분리한다.

운영 명령 예시:

- 모의투자 모드로 실행
- 실전투자 모드로 변경
- 현재 전략 후보 평가
- 새 외부 특성 연구
- 특정 종목 목록으로 다음 세대 생성

처리 규칙:

- 명령은 구조화된 Intent로 변환하고 감사 로그에 남긴다.
- 모드 변경은 사용자 요청이 없으면 일어나지 않는다.
- 실전 모드 전환과 주문 승인 상태는 분리한다.
- 실전 주문은 Champion 해시, 평가기·데이터·비용 모델 해시, 유효기간 있는 인간 승인, 독립 안전 점검을 모두 요구한다.
- Feature Registry 등록은 주문 승인이나 실전 승격을 자동으로 발생시키지 않는다.

Codex Desktop이 직접 호출 가능한 연구 LLM HTTP 엔드포인트가 없는 경우, 운영자는 Codex Desktop에서 Intent를 생성하고 로컬 CLI/파일 경로로 전달하는 방식으로 연결한다. 별도 엔드포인트가 제공되기 전까지 자동 런타임 호출을 사실로 간주하지 않는다.

### 단계 9. 실전 이전 검증

**목표:** 연구 결과를 바로 실전 주문으로 연결하지 않고 단계별로 검증한다.

1. Feature Registry 및 데이터 정렬 테스트
2. 반복 가능한 전체 세대 생성
3. QQQ·Nasdaq 비교가 포함된 기존 Funnel 결과 확인
4. 외부 특성 제거·기여도 보고서 확인
5. 모의투자에서 신호 시점·다음 거래일 시가 주문 변환·포지션 관리 확인
6. 모의투자와 연구 결과의 드리프트 측정
7. 사용자가 명시적으로 실전 전환 요청
8. 별도 실전 주문 승인 발급
9. 만료·해시·권한·긴급 차단 검사
10. 제한된 실전 운영과 감사 로그 검토

실전 계좌 키가 재발급되지 않았거나 실제 시장 데이터·캘린더·주문 권한 검증이 완료되지 않았으면 실전 단계는 `BLOCKED`로 남긴다.

## 8. 완료 기준

- 기존 평가 항목과 Funnel이 모두 유지된다.
- 수익성이 평가 점수의 최우선 항목으로 반영된다.
- QQQ 총수익률과 Nasdaq Composite가 동일 평가 구간에 추가된다.
- LLM이 VIX·금·DXY·지수·섹터 ETF·미국·일본·한국 2년물·10년물을 선택할 수 있다.
- 어떠한 외부 데이터도 전략에 고정 필수로 삽입되지 않는다.
- 새 특성은 구현·테스트·누수·정렬·재현성 검증을 통과한 뒤에만 Registry에 등록된다.
- 등록된 특성도 백테스트·OOS·강건성·기존 Funnel을 통과해야 전략에 사용된다.
- 전략별 위험 감수율·손실 허용도·일일 손실 행동이 평가 자료로 보존된다.
- 시스템 긴급 차단은 전략과 LLM이 변경할 수 없다.
- 미국 상장 주식·ETF와 사용자 지정 목록만 거래 대상으로 사용된다.
- 일봉 종가 확정 후 다음 거래일 시가 주문 규칙이 재현된다.
- 실전투자 모드와 주문 승인 게이트가 분리된다.
- 실전 키 재발급, 데이터 공급자, 시장 캘린더, Codex Desktop 운영 연결이 확인되기 전까지 실전 운영은 PASS로 표시되지 않는다.

```text
  → as-of 정렬·누수 검증
  → Strategy IR 확장
  → LLM 제안·신규 특성 등록
  → 다중 특성 백테스트
  → 기존 평가에 벤치마크·기여도 추가
  → Memory·Analyzer 확장
  → Codex Desktop 운영 연결
  → 모의투자 검증
  → 실전 승인 게이트
```

각 단계는 앞 단계의 테스트가 PASS인 경우에만 진행한다. 실패한 기능을 생략하거나 영구적으로 막아두지 않고, 실패 원인·수정 작업·재검증 결과를 상태와 감사 로그에 남긴다.

## 11. 구현 상태

이번 개선 작업에서 다음 내부 범위가 구현되었다.

- 다중 자산 시계열 계약과 외부 시계열 Parquet 저장·복원
- VIX·금·DXY·QQQ·Nasdaq 및 미국·일본·한국 2년물·10년물 선택 후보 Registry
- SMA·EMA·RSI·MACD·ATR·ADX·Bollinger·거래량 돌파·52주 고점·변동성·국면 계산기
- as-of 정렬과 FeatureRef lag 적용
- 외부 특성 참조·전략별 위험 정책 필드·일일 손실 평가
- 구현·테스트·누수·정렬·결측·재현성·자원·보안 검증 후 신규 특성 등록
- 기존 Funnel 유지와 절대 수익성 우선 점수 보강
- QQQ 총수익률·Nasdaq Composite 비교 및 특성 제거 기여도 계산
- Feature ID·벤치마크·위험 평가를 추상 Knowledge Memory에 저장
- Codex Desktop이 사용할 수 있는 구조화 FeatureProposal 경로와 `list-features`, `set-mode`, `mode` CLI
- 회귀 테스트 135개, 커버리지 89%, Ruff·mypy·secret scan 통과

다음 항목은 코드 누락이 아니라 실제 외부 운영 조건이다.

- 대화에 노출된 KIS 실전·모의 키 폐기와 재발급
- 실제 미국 가격·ETF·VIX·금·DXY·미국/일본/한국 금리 데이터 공급자와 캘린더 연결
- QQQ 배당·총수익률 데이터 정책 확정 및 실데이터 적재
- Codex Desktop 운영 환경에서 사용할 Intent 전달 방식 확인
- 모의투자 검증 완료 후 별도 실전 주문 승인

위 외부 조건이 충족되기 전에는 내부 연구·모의 기능만 PASS로 표시하고, 실전 주문은 DENY 상태를 유지한다.

이 문서는 기존 `docs/superpowers/plans/2026-09-01-quant-autoresearch-harness.md`를 대체하지 않는다. 기존 전체 구축 범위는 유지하고, 본 문서는 인터뷰로 확정된 특성 선택·거시 데이터·전략 위험·벤치마크 평가 개선을 추가하는 실행 계획이다.
